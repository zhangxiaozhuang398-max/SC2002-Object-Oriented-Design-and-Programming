Restaurant Rush

A turn-based restaurant management game in Java · SC2002 Object-Oriented Design & Programming

What this is

Restaurant Rush is a turn-based restaurant management game in Java. The player is the manager: staff time is scarce, so deciding who gets served first is the whole game. It comes in three runnable stages, each a git tag, plus an optional browser front-end.

  • Java 17 or newer. No Maven, no Gradle, no external libraries, no network access.
  • Two interfaces over the same rules: a command-line game (primary) and an optional web UI.

Web UI (front-end)

The browser front-end is an extra boundary object, added after the stage-3 tag. It contains no game rules: the page only draws GET /api/state and forwards each click to POST /api/action, and whatever the engine replies is shown verbatim — including the reason a move was rejected.

stage-3\web.bat              :: same as: start.bat web
stage-3\web.bat --preview    :: same as: start.bat preview
  • Served from http://127.0.0.1:8765 — the next free port if that one is busy — and the browser opens automatically.
  • Uses the JDK's built-in jdk.httpserver, so it is still dependency-free and fully offline; nothing ever leaves the machine.
  • Mirrors the console screens: a welcome page with the menu, goals and rules; a turn panel that walks through Happy Hour → Host → Waiter → Chef → Cashier and offers only the targets the console lists for each role; an end-of-turn summary and a shift log; and a results page with every guest's final status.
  • Live goal tracker, Happy Hour status, turn timeline with arrival markers, and boards for the queue, tables, kitchen and guests who have left.
  • Undo (button or Ctrl+Z), Chinese / English toggle (remembered), light and dark themes, and a layout that works down to phone width.
  • --no-browser starts the server without opening a browser.

Command-line game (the primary interface)

stage-3\run.bat
stage-3\run.bat --replay examples\victory.txt
stage-3\run.bat --replay examples\defeat.txt

Replace stage-3 with stage-1 or stage-2 for the earlier stages. Each stage folder is self-contained — src, test, examples, its own scripts and README — so it can be built and played on its own.

macOS / Linux: sh stage-3/run.sh, sh stage-3/run.sh --replay examples/victory.txt.

A direct build, without any script:

mkdir -p build/classes
javac -encoding UTF-8 --release 17 -d build/classes src/restaurantrush/*.java
java -cp build/classes restaurantrush.Main

Tests

verify.bat          :: same as: start.bat test

Runs the three dependency-free suites: 99 + 110 + 159 = 368 assertions, exit code 0 when everything passes. They cover the brief's Pasta timeline, staff capacity, invalid input retries, queue and table rules, abandonment and cancellation, payment order, price and satisfaction snapshots, both endings, polymorphic customer behaviour, Host actions, combo rounding, and Happy Hour duration and lock-in.

Web UI as design evidence

The web front-end was added after stage-3 and is a second boundary implementation over the same control and domain classes. Adding it required no change to any rule class; the only touch on existing code was extracting the three victory targets in GameResult into named constants, so that the rule and the UI read the same numbers from one place. That is a concrete, checkable example of keeping rules out of the UI.

Notes for anyone running this on Windows

  • The .ps1 scripts are wrapped by .bat files that pass -ExecutionPolicy Bypass, because PowerShell otherwise refuses to load an unsigned script.
  • The scripts change into their own folder and pass only relative paths to javac. Windows PowerShell 5.1 mangles non-ASCII characters in absolute paths, which breaks the build when the project sits in a folder with a non-ASCII name.
  • start.ps1 is saved as UTF-8 with BOM on purpose: PowerShell 5.1 reads a BOM-less UTF-8 script as ANSI and then mis-parses the Chinese menu labels.

这是什么

Restaurant Rush 是一个用 Java 写的回合制餐厅经营游戏。玩家扮演经理：员工的时间极其 有限，所以先服务谁就是整个游戏的博弈点。项目包含三个可独立运行的阶段 （各对应一个 git tag），以及一个可选的浏览器前端。

  • Java 17 或更高版本。不需要 Maven、Gradle、任何外部库，也不需要联网。
  • 两套界面共用同一份规则：命令行版（正式入口）和可选的网页版。

网页版（前端）

浏览器前端是一个额外的 boundary 对象，在 stage-3 tag 之后追加。它 完全不包含游戏规则：页面只负责渲染 GET /api/state，并把每次 点击转发到 POST /api/action；引擎返回什么就显示什么——包括"为什么这一步不 合法"的原始原因。

stage-3\web.bat              :: 等同 start.bat web
stage-3\web.bat --preview    :: 等同 start.bat preview
  • 地址是 http://127.0.0.1:8765（被占用则自动顺延到下一个空闲端口），并 自动打开浏览器。
  • 用的是 JDK 自带的 jdk.httpserver，所以依然零依赖、完全离线，数据不出 本机。
  • 与命令行界面一一对应：开局有欢迎页（菜单、目标、玩法）；回合面板按 欢乐时光 → 迎宾 → 服务员 → 厨师 → 收银员 的顺序逐步进行，每个岗位只列出命令行同样会提示的可选目标； 每回合有结算小结和营业日志；终局有结算页，列出每位顾客的最终状态。
  • 实时目标进度（付款人数、营收、平均满意度）、欢乐时光状态、带到店标记的回合时间轴，以及 等待队列、餐桌、厨房、已离店顾客面板。
  • 支持撤销（按钮或 Ctrl+Z）、中英切换（会被记住）、浅色 / 深色主题，手机宽度也能正常使用。
  • --no-browser 只起服务不开浏览器。

git diff --no-index stage-2/src stage-3/src

网页版作为设计证据

网页前端在 stage-3 之后追加，是在同一套 control 与 domain 类之上的 第二个 boundary 实现。加入它没有改动任何规则类；唯一动到 既有代码的地方，是把 GameResult 里的三个胜利目标抽取成具名常量，好让规则和 界面从同一处读取同样的数字。这是"规则不进入 UI"的一个具体、可检查的例子。
